# 前端审美构思

从人类的艺术与设计经验中提炼一个能够被感受到的视觉构想，写成清晰、具体、有画面感的设计描述，再据此实现前端。先思考这件视觉作品的气质、形态和表现力，让工程实现承接已经成立的艺术构想。

设计描述是独立交付物，必须在编写页面布局和样式之前向用户呈现。它应让人想象画面，也能讨论其中的情绪、张力与趣味。前期可以检查项目、内容和现有页面；不要先做完页面，再补写设计理由。

## 确定本次交付

- 用户只要求审美构思、设计描述或供另一个实现者使用的提示时，交付描述即完成，不擅自修改前端。
- 用户要求设计并实现时，先呈现设计描述，再在当前授权范围内继续实现。阶段分离不等于强制等待确认；只有用户明确要求先审核，或存在无法合理推断的关键选择时，才等待答复。
- 已有设计描述时，以它和用户最新修改为起点，补足影响实现的缺项，避免重新发明方向。精确复刻既定稿件或局部功能修复不需要重启审美构思。

## 找到艺术构思的起点

简要识别网站给谁使用、承载什么真实内容，以及必须保留的品牌、功能和技术约束。已有网站先检查相关页面、设计系统和素材，把构思限定在本次范围内。用这些信息理解作品的语境，随后进入艺术构思，避免停留在需求表和组件规划。

认真对待用户的风格词、比喻和感受词，例如“扁平”“飘逸的尾感”“冷峻”“像被风吹开”。先理解这些词可能指向怎样的形态、力量、触感或时间感，保留其中有价值的模糊性，再选择一种适合当前内容的具体解释。不要立即把它们缩写成无阴影、加渐变、放大标题或添加某个动画。

寻找一个足以组织整个画面的艺术构想：可以来自剪纸的轮廓、版画的叠色、书写的收笔、舞蹈的重心，也可以直接来自抽象的色块与空间关系。类比并非必需；采用类比时，提炼其中的形态、节奏和感受，不必把所指物品画进页面。让当前内容参与构思，而不只是填进事先选好的外壳。

已有的艺术与设计知识可以用于创作。用户提供参考链接、要求调研，或判断依赖具体作品时，实际查看来源，区分观察与推断并附上链接。无法访问时说明限制，不虚构案例研究、艺术史归属或“公认最佳”的依据。

只询问会实质改变方向、且无法从上下文推断的信息。对于可以合理解释的感受词，先给出自己的理解和构想，供用户修改，不要求用户先掌握专业术语。不要为了使画面显得完整而编造人物经历、客户评价或业务数据；必要的示例内容须明确标注。

## 用艺术语言展开画面

根据构想选择有表现力的观察角度，不把下列内容变成必填表。重点在于元素之间怎样发生关系，以及这种关系带来什么感受。

- **形态与线条：** 轮廓是利落切开、圆润膨胀，还是松动游走？线条的粗细、弯折和末端怎样形成重量、速度或姿态？扁平的形色也能通过遮叠、咬合和尺度产生丰富关系。
- **色彩与光感：** 思考色域的面积、温度、明暗与相互衬托。颜色可以像不透明颜料一样直接，也可以像透光薄片一样轻盈；决定哪一处沉着、哪一处跳出，而不止列出几个色值。
- **空间与构图：** 画面在哪里聚拢、哪里散开，什么被压住、什么像要越出边界？留白可以形成距离、悬念或延续。允许有意的不对称、偏移和尺度反差，形成适合这件作品的平衡。
- **材质与字形：** 图像的裁切、边缘和颗粒带来怎样的触感？文字也有轮廓、笔势、骨架和疏密，能够参与构图。可以追求纯净平滑，也可以保留适度粗粝，不默认添加纸纹或噪点才有艺术感。
- **动势与收束：** 观察线条、图形、文字如何起势、展开和结束。飘逸可以存在于静态轮廓中；若使用动画，关注动作的轻重、迟滞、停顿与余势。“尾感”可以是一段渐细的末梢，也可以是主体停下后尚未完全消散的节奏，不默认等于跟随鼠标的拖尾。

艺术选择可以服务于情绪、想象、装饰趣味或视觉张力，不必逐一证明它能提高操作效率。同时判断它是否与整体相融、是否遮蔽内容。允许节制，也允许浓烈；不要把极简、留白或整齐本身当成审美答案。

默认形成一个连贯方向。用户要求探索时，再提供艺术构想真正不同的候选，而不是同一页面换几套颜色。多个页面共享核心的形态与色彩关系，并根据内容变化节奏，避免每个页面机械重复同一种装饰。

当请求包含风格词、感受词，或草稿仍像组件说明时，读取 [艺术语言与构思示例](references/art-direction.md) 中适用的部分。示例用于帮助理解表达方式，其配色、题材和布局均不构成默认模板。

## 先写成艺术构想，再补实现依据

用用户使用的语言，以连贯的自然段描绘成品。先让人感受到整体，再展开最有辨识度的形、色、空间和动势，继而写这些关系怎样伴随真实内容延续。让文字读起来像在观看一件作品，随后才意识到它可以被浏览和使用。

允许诗性、比喻和感官联想，但让它们落在可想象的对象及关系上。“轻盈”可以由细长末梢与大片空白共同形成；描述要保留这种感受，而不是要求每个词都对应一个 CSS 参数。避免只串联艺术形容词，也避免刚提出意象就立刻转向栅格、断点、组件名和验收清单。

检查描述是否具有鲜明的画面，视觉选择是否相互支持，是否与当前内容产生联系。只有整齐的布局和清楚的层级，还不足以说明艺术构想已经成立；只有漂亮比喻而无法想象形色，同样需要重写。

艺术构想完整表达后，再用简短补充说明它如何成为界面：真实内容与关键操作怎样进入画面、需要什么素材、窄屏如何保留核心关系，以及动效减少时如何保持构想。确有必要时再给出比例、字体回退或其他参数。素材设想与现有资源要分清，尺寸细节留给渲染调整。

只要求构思时，在此交付；用户要求先审核时，等待反馈。已要求实现且无需等待时，将描述保存到项目已有的设计文档位置，没有约定时可使用 `design-concept.md`，再继续实现。纯讨论直接在回复中交付即可。

## 在实现与观看中保留艺术意图

沿用项目已有技术栈与组件能力，使构想进入构图、文字、图像、内容节奏和必要的交互。不要只把艺术性留在背景插图或零散装饰中；也不要为了覆盖每个细节而牺牲需要安静阅读和高效操作的部分。可读性、语义结构、键盘操作和触控可用性应融入实现。

若字体、素材或技术条件使关键构想无法实现，选择能够保留设计意图的替代方式并说明差异；影响整体方向的变化应先修订描述。不要在实现中无声地更换风格，也不要为了让文档与结果一致而事后抹去未解决的偏差。

用实际渲染回看作品。先看整体的轮廓、色域、疏密和张力，再看局部的笔势、裁切、末端及需要时的动态节奏：原先想要的感受是否出现，哪里僵硬、拥挤或用力过度？对整体不成立的问题，优先调整构图与元素关系，避免通过不断添加特效掩盖。

随后检查关键页面与状态、代表性的宽屏和窄屏、字体加载与交互反馈，以及长标题和真实数据下的阅读与操作。描述本身的问题应明确修订，避免为了忠实于文字而保留不合适的设计。

发现偏差时修复对应问题，并复核受影响部分。编译、类型检查和自动化测试可以验证技术行为，不能替代视觉判断。若无法查看渲染结果，明确报告未验证的部分，不宣称视觉验收通过。

最终交付艺术构想与设计描述及其位置；实施任务还应交付前端结果、实际验证情况和重要偏差。让用户能够沿着“艺术与审美经验 → 设计描述 → 页面表现”理解结果并继续修改。
