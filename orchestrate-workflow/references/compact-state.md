# Optional handoff notes

Use a short host-side note when ownership changes, work grows, or an unresolved issue could otherwise be lost. The host's conversation context, files, and native tool status may already be enough; no ledger or schema is required. When dispatching work, select the relevant task context from these sources rather than forwarding the host's history or orchestration instructions.

Useful content can include:

- The assigned task, intended outcome or deliverable, relevant original user intent or exact excerpts where needed, and actual decisions already made.
- The current owner and delegated decision scope, essential inputs and constraints, usable outputs, and important work still open.
- Priorities, completion criteria, and useful intermediate results or cross-executor decisions; questions, observations, and validation evidence where relevant to the work.

Include identifiers or source versions only when they help locate work or distinguish revisions. Keep detailed logs with their artifacts. Notes support the active agent's judgment; they do not replace it or create user authorization.
